Форма зачисления ценных бумаг (PERSON_NONTRADE_SECURITY_REFILL_EXT)
Патч: lk-m-securities-crediting.patch (сделан через git diff от снимка проекта 20.11)

Как применить (Git Bash, в папке lk_m):

  git checkout tt
  git pull
  git checkout -b FRC-crediting
  git apply --check lk-m-securities-crediting.patch
  git apply lk-m-securities-crediting.patch

Если --check ругается на конкретный файл — значит этот файл в ветке поменялся
после 20.11. Тогда:  git apply --3way lk-m-securities-crediting.patch

Что в патче:
- API: crediting/params, POST crediting, GET crediting (статус), crediting/files,
  crediting/file, crediting/commit, crediting/verify — core/api/transfers.ts, apiConstants.ts
- Типы: modules/Transfers/types/securitiesCrediting.ts
- Право: getSecuritiesCreditingPermission в modules/Transfers/permissions.ts
- Роуты: /transfers/securities/crediting и /transfers/securities/crediting/order
- Меню «Переводы»: вместо «Реквизиты для зачисления» — «Зачисление ценных бумаг»
  (страница реквизитов и её роут остались)
- Новая форма: pages/SecuritiesCrediting/SecuritiesCrediting.tsx
- Подписание: pages/SecuritiesCreditingOrder — это та же страница, что у списания,
  с variant="crediting" (свой verify, свой URL файла, свои тексты)
- Общие хелперы списания вынесены в SecuritiesWriteOff/writeOffFormHelpers.tsx,
  списание теперь импортирует их оттуда (поведение списания не менялось)

Допущения (проверить с аналитиком/бэком):
- Список инструментов берётся из writeoff/params (как договорились)
- Загрузка файлов — тот же /nontrade/securities/file, затем crediting/commit
  (как у списания: POST с noCommit=true, если есть файлы)
- Поля «Комиссия» нет — в API зачисления её нет
- «Место расчётов» в POST не отправляется (в API нет такого поля), оно только
  фильтрует «Тип зачисления»: если changeOwnershipAllowed=false, «С переходом прав» скрыт
